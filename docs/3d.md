# 3D modeli (atlas telesa, organi, celice, kemija, fizika, matematika)

English below on purpose: it is read by agents. Plan for j: https://claude.ai/artifact/Fhiz6ws6NsaDrivm97mAc1

## Goal

Evklid's own 3D atlas in the spirit of Astra's »Atlas človeškega telesa«, but more polished and in Evklid's look:
dark stage, Instrument Sans, accent `#6E9BFF`, rounded pill buttons. j's rule: every organ and organ system is also a
standalone simulation; plus 3D cells of every type, atom and orbitals, molecules, DNA, crystals, fields, solids,
3D graphs, solar system and cell processes. Web and the mobile app must look and work the same (the app opens the
same page in a WebView, like `/kalkulator`). Slovenian labels; no copying of Astra texts, images or models.

## Hub and viewer page (`/3d`)

- **Hub** (`stran.js` `zbirka`, j 2026-11-14: »3D svet kot drevo«): opens on the tree from `public/3d/drevo.js`: four
  subjects (Biologija, Kemija, Fizika in vesolje, Matematika), a tap on a branch shows its sub-branches, the last branch
  shows its models as cards; »Celo telo (atlas)« is a branch that opens `#atlas`. Each branch is a rendered icon from
  `public/3d/ikone-drevo/<slog>/<id>.webp` in the app's style (read from localStorage `evklid.theme`, Igriv uses Čist; a
  `storage` event swaps them live), on a tile tinted with the group colour, with the name always under it and the number
  of models in a badge. The path (»3D svet › Biologija › …«) sits in the sticky bar under search; every step is a new
  history entry (`#?v=biologija/telo`), so the phone's Back goes up one branch, and Back from a model returns to the same
  branch. The microscope is a round button next to search. The root also shows »Nazadnje odprto« (localStorage
  `evklid.3d.nedavno`, last 8 ids) and, for a model `drevo.js` does not place yet, »Novo v 3D svetu«
  (`test/3d-drevo.test.js` fails on such a model). Search (`iskanje.js`, title, `opis` and area name, no
  diacritics/case) covers all models plus the atlas and microscope cards, state `#?q=…` (replaced). Search uses the Evklid
  keyboard (`tipkovnica-strani.js`; `html.k3-stran` defines the app tokens the keyboard reads). Adding a model: put its
  id in a branch of `drevo.js`; a new branch also needs an icon (`scripts/3d-ikone-drevo/`, all styles) and
  `a3.tree.<id>` in every language.
- **»Uči se → 3D svet«** (`public/uci-se.js` `show3d`, the tab in the web app and the Android app): the same tree from
  `drevo.js` in the app's own theme (light or dark, tiles on `--surface`), path as buttons, the open branch kept in
  `sessionStorage` `evklid.3d.veja`; atlas, a model or »Odpri mikroskop« open `/3d?vgrajeno=1#<id>` over the whole
  screen (`open3d`). A style change (`evklid:era`) redraws the icons. The native app's own 3D tab
  (`mobile/src/components/Web3D.tsx`) loads the `/3d` hub itself.
- **Thumbnails**: `public/3d/slicice/<id>.webp` (560×350, transparent, ≤ 60 KB; `atlas.webp` is a cut-out of the body).
  Make them with `node scripts/3d-slicice.cjs [id …] [--manjkajoce]` after adding or changing a model; the server lists the
  existing ones in `seznam.json` (`slicice`), a model without one gets its area icon. `test/3d-zbirka.test.js` fails on a
  thumbnail without a model.
- **Model page**: `odpriModel(el, mod, { stran: true })` (lessons keep the old layout). Full-bleed stage plus a panel
  (`.k3-plosca`: Opis with `info.opis` and »Preizkusi«/»Razmisli« from `info.poskusi`, the `nadzor` controls, »Deli« list): right of
  the stage at ≥ 900 px and on phones in landscape, below the stage on phones (the panel scrolls, the stage stays
  visible). Stage tools: zoom out/in (`kit.priblizaj`), play/pause, reset; a gesture hint until the first touch. Header:
  previous/next model of the same area (replaces the URL, so Back still goes to the hub), »1 od 29«, full screen (web
  only). Organ models (`postavitev: "organ"`) get the same panel; their `nadzor` stays on the stage and »Podrobnosti
  organa« is the last item of the panel.

- **Lost WebGL context** (`scena.js`, j 2026-11-25): after an app switch or under memory pressure (iPad) the browser may drop
  the context. three.js calls `preventDefault`; `scena.js` stops drawing, after 0,6 s shows a card (`.k3-izguba`, »Znova
  naloži« reloads the page) and on `webglcontextrestored` makes a new PMREM generator and room environment, reloads the
  studio HDRI if it was active, resizes and redraws (three.js re-uploads geometries and textures itself; render-target
  content such as PMREM maps is lost). The old generator, its render target and the old studio render target are then
  disposed (in `try`, so a failure only warns). `test/3d-webgl.test.js` checks it with `WEBGL_lose_context` in Chromium.
- **Embedded 3D that does not answer** (`uci-se.js` `open3d`, `vgrajeno.js`): the `/3d` page posts `{ tip: "pripravljen" }` to
  the parent after each route renders and `{ tip: "napaka" }` with an error card. `cuvaj3d` in the parent shows a short
  message and »Zapri« over the frame when nothing arrives within 8 s (only »Zapri« after `napaka`), so a student is never
  stuck behind a black full-screen frame.
- **Old browsers** (j 2026-11-25): three.js r187 needs Safari 16.4+ (class static blocks). Before three.js loads, `stran.js`
  (atlas, model, microscope routes) and `sim.js` call `preveriPodporo()` (`napake.js`), which imports `public/3d/podpora.js`
  (a class with a static block; CSP forbids `eval`, so detection is a module import). A failed import that is not a
  `SyntaxError` is retried once after 400 ms (as `podpora.js?znova=1`). If it still fails but the file downloads, the browser is too old (`koda: "brskalnik"` → `a3.oldBrowser`, the technical line shows the browser's own
  error); otherwise it is a network error. The hub still works there. Files statically imported by `stran.js` must parse in
  old Safari: no regex lookbehind or `v` flag anywhere under `public/3d` and `public/mikroskop`, and no class static blocks
  in the static import graph of `stran.js` (`test/3d-podpora.test.js`, acorn).
- **Errors** (`public/3d/napake.js`, j 2026-11-25): `napakaBesedilo(err)` → `{ vrsta, key, detail }` decides what the
  student reads: network (`TypeError` »Failed to fetch« / »Load failed« / »Importing a module script failed« / »error loading
  dynamically imported module«, HTTP ≥ 400 in `status`, `response.status` or the message, `navigator.onLine === false`,
  `povezava: true`, and a JSON `SyntaxError` from an HTML page such as a captive portal) keeps `a3.loadError`; any other
  `SyntaxError` → `a3.oldBrowser` (update iOS/iPadOS and the browser, 3D needs Safari 16.4+; an invalid selector is
  `a3.otherError`); »memory«/»allocation«/context lost, or a `RangeError` about memory or a buffer (not »Offset is outside
  the bounds of the DataView« from a truncated GLB) → `a3.lowMemory` with a link to `?kakovost=nizka` (unless already `nizka`); `koda: "webgl"`
  → `a3.noWebgl`; a missing export (»does not provide an export named«, Safari »Importing binding name … is not found«: an old
  module from the service worker next to a new one, also a `SyntaxError`) → `a3.updated`; anything else → `a3.otherError`.
  Every card shows a small »Tehnično: <name>: <first line of message>« (`tehnicno`, ≤ 120 characters, no stack, URLs cut to
  their path, query strings, e-mail addresses and long token-like runs hidden) so a screenshot names the cause. `napakaVsebina(err, { t, znova })` builds the
  card (text, technical line, link, »Poskusi znova« when `znova` is given and retrying can help). For module import errors
  (`modul: true`) »Poskusi znova« calls `osveziMimoStarih()`: the service worker drops copies of a version the server no longer
  has (`app-stale` with `/healthz/stanje` `datoteke`, as `public/app.js` does), then the page reloads. Used by `stran.js` (retry: the route
  again after a network error, else a page reload, because the browser keeps a module that threw in its module map),
  `sim.js`, `pregledovalnik.js` (rebuilds the model), `mikroskop.js`, `atlas.js` (layer rows) and `uci-se.js` (»3D svet« tab).
  The native app's `Web3D.tsx` tells offline (`nativeEvent.code`/`description`) from other errors and reloads when the
  system kills the web process (`onContentProcessDidTerminate`, `onRenderProcessGone`; error card on the third crash).

## Model builder contract (code-built models)

```js
// public/3d/modeli/celice/zivalska.js
export const info = {
  id: "celica-zivalska",            // unique, ASCII, used in /3d#<id> and as sim engine id "3d-<id>"
  naslov: "Živalska celica",
  podrocje: "celice",               // celice | organi | sistemi | kemija | fizika | matematika | vesolje | procesi
  predmet: "BIO",                   // BIO | KEM | FIZ | MAT | NAR
  opis: "One or two Slovenian sentences for the hub card.",
  poskusi: "One Slovenian sentence: what to do in the model (shown as »Preizkusi: …« under the model; { razmisli: \"…\" } for a thinking-only question shows »Razmisli: …«, public/sim/napis-poskusa.js).",
  merilo: { m: 20e-6, oznaka: "20 µm" },   // real size of the group's unit sphere diameter, for the scale bar
};
export function zgradi(THREE, ctx) {
  // ctx = { kakovost: "nizka" | "visoka", gibanje: true|false (false = prefers-reduced-motion),
  //         zacetek: { <nadzor id>: value } (start values from a catalog entry or /3d#<id>?telo=valj) }
  // Text labels: canvas sprites inside `group` (the kit has no label API).
  return {
    group,          // THREE.Group centred at the origin, fitting a sphere of radius 1
    deli: [         // tappable parts (list + part window next to the stage)
      { id: "jedro", ime: "Jedro", opis: "Hrani DNK in upravlja delovanje celice.", barva: "#7a68d8",
        meshes: [mesh1, mesh2], tocka: [x, y, z] },
    ],
    nadzor: [       // optional controls rendered by the kit (Evklid slider/segmented look)
      { tip: "drsnik", id: "t", oznaka: "Čas", min: 0, max: 1, korak: 0.01, vrednost: 0, ob: (v) => {} },
      // drsnik with prerez: true (moves a cut plane): while dragged, everything but this slider is hidden so the whole
      // model shows; other sliders keep the windows visible (j 2026-11-24)
      { tip: "izbira", id: "pogled", oznaka: "Prikaz", moznosti: [["kroglice", "Kroglice in palčke"], ["kalota", "Kalota"]], vrednost: "kroglice", ob: (v) => {} },
      { tip: "gumb", id: "spusti", oznaka: "Spusti preizkusni naboj", ob: () => {} },
      { tip: "stikalo", id: "mreza", oznaka: "Pokaži mrežo", vrednost: false, ob: (v) => {} },
      { tip: "izpis", id: "v", oznaka: "Prostornina", vrednost: () => "V = 24,0 cm³" }, // read-only, re-read after each change and ~4×/s
      // izpis with tex: true: parts between $…$ are KaTeX (real fractions, j 2026-11-12), "\n" starts a new line; formulas
      // wrap under the label when they do not fit beside it; /3d loads KaTeX on first use (telesa.js enacba/fTex)
      { tip: "izpis", id: "V", oznaka: "Prostornina", tex: true, vrednost: () => "$V = {\\frac{a^3\\sqrt{2}}{12}} = {7{,}5\\,\\mathrm{cm^3}}$" },
    ],
    korak(t, dt) {}, // optional animation step (seconds); skip motion when ctx.gibanje is false; return false when idle (no redraw)
    korakBrezGumba: false, // optional: true hides the play/pause button (korak only eases a transition, e.g. telesa camera)
    izberi(delId, hit) {}, // optional: called on selection; hit = { object, instanceId, point } from the raycast (null from the parts list); may return another part id
    merilo: null,     // optional: object like info.merilo, or a function () => ({ m, oznaka }) | null (null hides the bar); re-read like `izpis`
    povzetek: null,   // optional: () => string, a short chip at the top left of the stage (e.g. V and P of a solid); stays visible while a slider is dragged; re-read like `merilo`
    pogled: [0.35, 0.3, 1], // optional: camera direction from the origin (model space) on open and »Ponastavi«; array or () => array, read each time
    luci: true,      // optional: false = kit removes scene.environment and its own lights while shown (model brings its own Sun)
    dispose() {},    // optional
  };
}
```

»Poglej pod povečavo«: any part (code `deli[]` or organ JSON `deli[]`) may have `povecava: "<model id>"` (and `la`, the
Latin name shown under the card title). On the /3d page the part card then shows a button that opens `/3d#<model id>`
with `history.pushState({ k3Iz: "povecava" })`, so Back (button, key, Esc) returns to the organ; in the app frame
(`?vgrajeno=1`) the same history works inside the iframe. Lessons get no button (`opts.povecava` is only passed by
`stran.js`). Chain: organ (oko → mrežnica) → tissue section (`organ-mreznica`, `organ-mesicki`, `organ-nefron`,
`organ-jetrni-reznjic`, code-built in `modeli/organi/`) → cell (`celica-*`). Test: `test/3d-povecava.test.js`.

Any nadzor item may have `vidno: () => boolean`; the kit hides it when false and re-checks after every `ob()`.
The kit frames the radius-1 sphere to the narrower of the horizontal and vertical field of view (portrait phones).

## Part window and framing (j, 2026-11-05)

- **Never over the model.** No coloured dots or label cards on the stage. The selected part's window (`.k3-info` in
  `pregledovalnik.js`: colour dot, name, `la`, `opis`, »Poglej pod povečavo«, ×) is the first item of the panel next to
  the stage: right of the stage on wide screens, a sheet under the stage on phones (the panel scrolls to it), under the
  stage in lessons. Closed by ×, Esc or a tap on empty stage (× and Esc return focus to the part's list button). A tap
  on the model scrolls the panel to the top; a pick from the list only scrolls as far as needed to show the window; in
  lessons the page scrolls the window into view when it is below the screen edge. The part name is also announced
  through a separate, always-present `role="status"` element. The body atlas does the same with `.a3-kartica`
  (`uskladiKartico`): when the card is open the stage shrinks (phone portrait: card and bottom row become a sheet under
  the stage; desktop and phone landscape / low 3D-world iframe: a content-high column left of the stage, stage
  background under it) and the fly-to centres the part in the stage below the header. The start frame
  (`ponastaviPogled`) uses the same free area, so the skull is never under the toolbar.
- **What is tappable** is shown by a soft glow instead of dots: when a set of parts is first shown (open, view switch,
  phase), one instance of each part glows twice in its colour (`namigniDele`, additive overlay mesh flagged
  `userData.k3Sij`, not pickable); parts wrapping almost the whole model (membrane, wall) do not glow.
- **Selection** tints every mesh of the part (all instances of an `InstancedMesh`, e.g. all mitochondria) with an
  emissive copy of its material in the part colour; parts smaller than 0.6 of the model (opaque, front-sided meshes)
  also get a thin accent outline like the atlas (`narisiObris`, back faces pushed out ~1.8 px, `userData.k3Sij`), so
  thin pale parts such as the axoneme show it. Copies and outlines are disposed on the next selection, rebuild and
  `unici()`.
- **Shells hide around the selection** (biology only, `public/3d/ovoji.js`, re-checked after every control change):
  a bigger part is hidden (layer 31) when all six axis rays towards the selected part's centre hit it and it is reached
  before the selected part in most of them. Content inside the selected part (DNA in a phage head) is therefore never
  treated as its shell, even when part of it lies elsewhere. A part with `ovoj: false` is never a shell (content that
  runs through the model, e.g. phage DNA, which thin selected parts such as fibres could otherwise "enclose").
  Hidden meshes count as shell surface too (closing lids of cut-aways), so shrink a hidden helper mesh that must not
  (`test/3d-ovoji.test.js`). `deli[].tocka` is still required
  (contract, tests) but no longer drawn.
- **Framing** (`public/3d/kader.js`): `obsegVidnega` = box of what the camera really sees (visible branches, layers,
  visible materials; no lines, sprites or glow). On open and »Ponastavi« the camera frames that box's sphere (organs and
  models with `okvir` keep their own frame; never larger than the start sphere, never below 0.6 of it). After an `izbira`
  (e.g. spermij »Glava in vrat (povečano)«), a part selection or a deselection the camera moves only when the visible
  model changed noticeably (`drug`: centre moved > 0.2 r or radius × 1.25, e.g. a membrane or wall hidden or shown
  again) or the model or part is wholly out of frame (`vidnaKrogla`). While the camera is still in the last automatic
  frame it also keeps the model and part wholly in frame (the phone panel shrinks the stage); a frame the user zoomed or
  moved is otherwise kept. Builders need not frame views themselves.
- **Check**: `node scripts/preveri-3d-okna.cjs [id …]` (Playwright, swiftshader, phone 390×844 and desktop 1280×800;
  `atlas` also 844×390 landscape): for every cell and organ (and `atlas`) it opens the model, clicks every `izbira`
  option and the first and last part, and fails when ≤ 99 % of sampled vertices are in frame, a visible mesh is wholly
  out of frame, there are dots on the stage or the part window overlaps the canvas. `test/3d-kader.test.js`
  covers `kader.js` and that the viewer draws nothing over the stage. Run it after changing a cell/organ model or the
  viewer layout.

Kit behaviours builders may rely on: the viewer (`pregledovalnik.js`) turns models freely around the target like a ball in the hand (`opts.prostoVrtenje`, `public/3d/vrtenje.js`: camera and its up vector rotate together, no locked vertical axis, no pole stop; Ponastavi and view switches stand the camera upright again with `poleti(…, { pokonci: true })`); the body atlas keeps an upright orbit; a round button in the stage toolbar of every model and the atlas (`poveziGumbVrtenja`) cycles the mode »prosto« → »pokoncno« → »hoja« (`kit.nacinVrtenja`, stored as `evklid.3d.vrtenje` for all models): »hoja« is a first-person view (drag looks around, W A S D / arrows / Q E, wheel, pinch, and the held Naprej/Nazaj buttons at the stage edge move; OrbitControls is off and the target stays in front of the camera); `renderer.localClippingEnabled = true` (material.clippingPlanes work); the canvas is
transparent and the stage colour (`#0e131c`, plus a soft radial glow) is CSS behind it, so it is exact with or without
post-processing; at `visoka` GTAO only darkens opaque single-sided meshes: transparent, non-normal-blending and
double-sided materials, lines, points and sprites are drawn after the AO pass and never darkened;
`raycaster.params.Points.threshold = 0.02` (a tap hits a point cloud only near a point); on a
~4×/s tick the kit re-reads `vrednost` of drsnik/stikalo/izbira (builders may move their own slider or switch off
»Predvajaj«) and updates a widget only when `vrednost` changed since the kit last read it (never forces it back) and re-reads `deli` (may be a getter); picking takes the nearest intersection by distance (`public/3d/izbira.js` `skoziLupino`: only hits whose material opts in with `userData.skozi = true` are skipped while a non-shell hit lies behind; cell glass membranes set it via `V.steklo`; the body atlas skips skin, `razred === "koza"`, for tap, hover and the »Najdi strukturo« quiz, which also counts skin in front of the chosen part; a second tap on the selected part under skin selects the skin; test `test/3d-izbira.test.js`) (a mesh may override `raycast`).

After every `ob(...)` call the kit re-reads `deli` (the array may be replaced), `merilo` and rebuilds the parts list, so one builder can switch content (molecule, element, lattice, field type). `three` is a dependency pinned to

  then a single word only if one part has it in a ≤ 2-word name; the client uses the same `zacetnaIzbira`). Groups have
  level texts `opisOs`/`opis`/`opisStudij` (member list below the text) and may set `smer` (camera direction, e.g.
  Zaklopke from above-front). Add groups for new models there (test `3d-skupine` checks member ids and translations).
- **Cut** (j 2026-11-06 »najboljši približek pravemu srcu, razrezanemu na pol«, shared by all organs): the cap is lit
  as a flat cut face (`materialPokrova`: per pixel the point on the cut plane along the view ray, plane normal plus a
  bump from the fibre pattern, so fibres lie on the plane and do not swim; matte, faint wet coat; `rez`, `rezVlakna`,
  `rezHrap`, `rezLak`, `rezRelief`). `prerez.temnenje: { razdalja, moc, odprtost, endokard, endokardMoc,
  endokardTkiva }` darkens surfaces with distance behind the cut (cavities get depth) and, on cavity walls (openness
  G < 0.4), blends the pale glossy endocardium colour. Heart geometry for the cut: the septum is a closed solid between
  the LV and RV septal surfaces (`pretin_trden`), embedded halves of trabeculae/papillary muscles are removed
  (`izrezi_vgrajeno`), so wall caps are solid (LV ≈ 12 mm, RV 3–5 mm, septum ≈ 10 mm).
- `prerez.brezPokrova`: parts without a cut cap (inner structures that intersect the wall; heart: conduction system,
  crista terminalis, pectinate muscles, conus); `pogledi.<p>.skrijDele` hides parts in a view (heart cut: aorta and arch branches; whole view: conduction system).

## Mesh check (all GLBs)

`node scripts/atlas/preveri-mreze.mjs [filter …] [--vse] [--json]` checks every GLB in `organi-3d/`, `telo/` and
`telo-hd/` (~4 s for all 29): per node (part) open edges and holes (boundary loops, with perimeter in mm; an open tube end
is a loop too), non-manifold edges, flipped faces (minority winding per connected component), closed components that are
inside-out (signed volume < 0, mirrored nodes accounted for; a negative closed component inside a positive one is a
cavity, i.e. the lumen of a vessel with a real wall, and is fine), degenerate triangles and non-triangle primitives
(strips, fans, lines: counted as a problem, never skipped); vertices are welded by position first, across all
primitives of a node. Vessel parts are marked (organs: `extras.tkivo` arterija/vena/portalna/pljucna*; body: `sistem` `zile` of
`extras.zid` without heart chambers and valves). `test/3d-mreze.test.js` fails when any part gets worse than
`scripts/atlas/mreze-izhodisce.json`; after a mesh fix lower the baseline with `--izhodisce` (it refuses increases
unless `--sprejmi-slabse`). Reading needs the devDependencies `@gltf-transform/core`, `@gltf-transform/extensions` and
`meshoptimizer` (decoder for `telo/`).
Small decimation leftovers in organ parts (degenerate triangles, folded triangle pairs, pinched double shells, minority
winding) are cleaned by `node scripts/atlas/pocisti-mreze.mjs [filter] [--suho]` (plan per file and node name in the
script, idempotent, shape/UV/textures unchanged); `--izhodisce` rewrites every model, so when another model has open
regressions update only your own entries.

## Vessel repair (after every export)

`node scripts/atlas/popravi-zile.mjs [filter …] [--suho]` post-processes the exported GLBs in place (geometry in
`scripts/atlas/zile-mreza.mjs`, plan per model in `NACRT` at the top of the tool, driven by part names; UVs, materials,
part names and quantization/meshopt are kept). Run it again after `izvozi-organe.py` or a body export; a second run
changes nothing. One file: `--vhod a.glb --izhod b.glb --nacrt srce|jetra|telo`. Steps:

- `dopolni`: a vessel wall cut off along its length by the export box (`skatla`: lens-shaped hole, trough of the aortic
  arch) is rebuilt on the cylinder of the tracked tube axis; a loop that winds around the axis is a tube end and stays.
- `zgosti`: faceted great vessels (12 sides in the heart, 6 in the body) are refined adaptively: an edge is split where
  the smooth surface through its end points and normals (PN-triangle curve) deviates from the chord by more than the
  tolerance in `NACRT.<plan>.zgosti(path)` (heart 0.15 mm desktop, 0.44 mm phone = aorta only; body 0.3 mm HD, 0.7 mm
  regular), the new vertex lies on the curve, straight edges stay; two passes (6 → 12 → 24 sides), conforming mesh.
- `stiki`: end rings of neighbouring parts of one vessel get identical vertices and normals; rings with different
  vertex counts get the union of their vertices (boundary edges split), three-way junctions are iterated until equal.
  A ring shared by three or more parts (bifurcation: abdominal aorta ↔ common iliac arteries, SVC ↔ brachiocephalic
  veins) gets one normal in all parts (sum of the parts' smooth normals; pairwise averaging left a brightness step
  at the ring) and its vertices are moved onto the ring's circle (`zaokroziRazcepisca`; the union of vertices on the
  circle and on the neighbour's chords shaded as »teeth« on the 12-sided phone model).
- seam smoothing: Taubin smoothing (no shrinkage) around part junctions and the rebuilt wall, both parts together,
  fading with distance; free ends and rings shared by three parts (a bifurcation whose branches start in the same
  ring and overlap) stay; normals of the smoothed parts are recomputed from geometry.
- `stena`: great vessels get an inner wall and flat rims at open ends (aorta 2.5 mm, pulmonary trunk and arteries
  1.5 mm, venae cavae and pulmonary veins 1 mm; thinner where the tube is narrow or the wall folds). Ends that are not
  visible (a junction with another part, or an end inside a neighbouring vessel) get a rim built from the wall
  vertices, so no flat-shaded ring shows through a junction or pokes out of the neighbour. An end that continues
  into a small solid vessel (brachiocephalic vein → subclavian and jugular vein) is treated as hidden all round; the
  part of that rim that is not really inside the neighbour gets its own inner vertex with the outer-wall normal
  (the inner-wall vertex has an inward normal and showed as a dark jagged seam).
  The rim quads of a junction are split along the same diagonal in both parts (chosen by vertex position), so the
  two parts hold the same rim triangles with opposite winding.
- `stikiSkupaj` (heart): parts joined by junctions get one quantization grid (same node translation and scale, so
  junction vertices are bit-identical in both parts: no hairline cracks) and `extras.stik = 1`. Each part stays a
  closed solid for the mesh check; `organ.js` merges the nodes of one part/tissue anyway and, for `stik` nodes, drops
  the coincident opposite triangle pairs (`brezPregrad` in `organ-prostor.js`). Without that the junction partition
  showed in the cut view as dashed ring fragments (lit front face of one part z-fighting the cut cap of the other).
- `polna`: small vessels (coronaries, cardiac veins, all other body vessels) become closed solid tubes. The end cap
  is a low dome with a centre vertex whose normal points along the axis (a flat cap built from the ring vertices
  kept the wall normals and shaded pale grey head-on). Only a free end gets the dome (`konecProst`): the dome
  apex, the ring vertices and edge midpoints pushed 0.05 r along the axis, and points on the dome faces must all be
  outside every other mesh of the file (ray parity; other vessels and non-vessel parts such as the heart wall) and
  at least 0.1 r from its surface, and no dome triangle may intersect a triangle of another mesh. An end that sits
  inside another vessel, butts against a wider or offset segment (stepped joint), is partly sunk into a neighbour
  or touches one keeps the flat cap, because the dome or its rim would poke through the neighbour's wall or show as a bright
  collar on the step. Open edges that are not a loop (a 2 µm slit between two
  near-duplicate vertices in the non-manifold `Cavernous sinus`) are stitched by snapping the boundary vertices
  together (`zasijRobove`), unless that would add a non-manifold edge.
- `zakrpaj` (liver): small holes are filled first; `usmeri`: winding made consistent, outside out. A component nested
  inside closed shells of the same part (the lumen of a hollow vessel; sampled points, union of shells) is never
  flipped; the mesh check uses the same rule.
- Organs: the vertex-colour data of changed parts (R baked shade, G openness for the heart) is baked again in JS with
  the same rays as the exporter (ray length from `velikost` in the organ JSON); coincident vertices of two parts get
  the average shade.

Because the walls are real, heart parts no longer use `znotraj` in `deli` (double-sided wall, #531); the support in
`organ.js` stays for single-wall tubes. Known limits: branches are overlapping tubes, not boolean unions; the aortic arch
has no branch stubs; `Cavernous sinus.l` in `telo-hd` keeps one 2 µm slit (stitching it would add a non-manifold edge);
the phone heart refines only the aorta (90,000 triangle limit). `--vhod a --izhod b` with nothing to repair copies the input. `test/3d-popravi-zile.test.js`
checks the steps on synthetic tubes. Update `trikotniki` in the organ JSON after a repair.
`zapisi()` leaves the old accessors in the document; the finishing scripts call `brezSirot(doc)` before writing (they
were up to 185 kB of dead bytes per GLB).

### Heart finishing (after the repair; j 2026-11-12 »izboljšaj vse kolikor mogoče«)

Order, always from the fresh export (the repair is not idempotent, never run it on a repaired file):
`popravi-zile.mjs --vhod <izvoz> --izhod public/… --nacrt srce` → `node scripts/atlas/srce-dodelava.mjs` →
`node scripts/atlas/rez-stena.mjs srce`.

- **Repair plan `srce`**: `Root of aorta` and `Root of pulmonary trunk` are CT wall shells (3.8 / 5.4 mm), parts of the
  one closed wall union, so they get no second wall; `Interventricular septum` is not capped (`polna` matches only
  `interventricular (artery|vein|branch)`). The brachiocephalic veins are already double-walled tubes with an open
  annulus at the caval end: `rob` → `obrocRob(m)` bridges the two coaxial loops with a rim (no `stik` groups remain).
- **`srce-dodelava.mjs`** (idempotent; extras `vgreznjeno` marks the one-time step): coronary arteries and veins are
  moved along the epicardial normal so the tube axis sits `VGREZ` (0.2) radii above the surface (half embedded in the
  groove fat instead of lying on top; smooth along the vessel, at most 4 mm); papillary muscles, trabeculae, the
  septomarginal trabecula and the conducting system that poke through the thin right-ventricle wall (a vertex whose
  ray away from the heart centre hits no wall, or one above the nearest outer face) are pushed 1.5 mm under the
  epicardium; pinholes in the wall (small open loops that are not on a seam between wall parts) are patched; thin folds (valve of coronary
  sinus, valve of inferior vena cava, fossa ovalis) get tissue `guba` (pale, two-sided, no texture); vertices of
  untextured tissues are welded by position + normal, phone trabeculae get one UV (size limit). Updates `trikotniki`.
- **Epicardium, auricles (round 2)**: the CT outer surface is coarse (edges ≈ 7 mm; the endocardium ≈ 1 mm), which made
  the fat look like faceted plates. `zunanjaOglisca` finds outer vertices (a ray along the normal hits no wall; COLOR_0
  does not hold this), `zgosti` splits outer triangles twice (midpoints lifted onto the curved surface, shared edges
  split in every wall part, so no cracks), `zgladi` (Taubin, no shrinking, seams move together) rounds the plate
  edges and recomputes normals. The two auricle bodies of our own (`Left auricle`, `Right auricle (lastno)`) get
  tissue `uho` (copy of `miokard` without baked texture, ventricle tone) and are smoothed, the folds (`guba`) too.
  Once per export (extras `zglajeno`). The coronary step uses the same outer surface.
- **Round 3**: the cut plane goes through the apex and the centres of both atria (true four-chamber view; the aortic
  root lies 4 mm behind it and is not opened); the cut view hides coronary vessels and the conducting system
  (`pogledi.prerez.skrijDele`), `rez-stena.mjs` leaves hidden parts out. `zgladi(…, splosci)` lowers bulges above a
  heavily smoothed surface (CT fat pads that stuck out of the outline; round 4: fully, above 0.2 mm). Coverage texture channel B = inner wall-tissue
  bodies in the cavities (`prerez.volumen.brezMasce`, regex of node names) and hollow bodies (`prerez.volumen.votlo`,
  the auricles: no cap at the plane): there the cap is never fat (the volume texture has random »fat« in the
  cavities; a cut papillary tip was a white ball). Tissue `rezVlaknaOs` (long axis of the organ): the fibre pattern
  of the cap is stretched along the fibre projected onto the cut plane, so the wall reads as fibre bundles instead
  of speckle. The cut textures (volume, tissue, coverage) load on the first Prerez.
- **`rez-stena.mjs`** writes `<organ>-stena.png` / `-stena-telefon.png` and `prerez.volumen.stena`
  (`{ slika, telefon, lo, korak, n, ploscice }`): per 1 mm voxel R = share inside the wall solid (winding number of
  the union of `rezVolumen` tissues + `prerez.volumen.stenaVozlisca`), G = share inside other capped bodies
  (coronaries, vessel walls). `materialPokrova` draws the cap at the cut-plane depth only where R > 0.5 and G < 0.5.
  Reason: »a visible back face means inside« is false once the cap is forced to the plane depth (it bypasses
  occlusion), and the renderer has no stencil; the old volume test left flaps beyond the outline, holes and dashed
  rings. Re-run after every change of the heart mesh.
- New JSON keys (all optional, any organ): tissue `rezLakHrap`, `rezSijaj`, `rezSijajBarva`, `rezSpekular`,
  `rezMascaMeja: [lo, hi]` (fat threshold in the volume alpha); per-view tissue override `lakHrap`;
  `prerez.temnenje.endokardTkiva` may list vessel tissues (pink venous lumen instead of blue).
- Mesh baseline: the wall parts (ventricles, atria, septum, conus, auricle, both roots) are open patches of one closed
  union, so their open edges are expected and invisible; `scripts/atlas/mreze-izhodisce.json` holds them for `srce*`.
