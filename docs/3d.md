# 3D modeli (atlas telesa, organi, celice, kemija, fizika, matematika)

English below on purpose: it is read by agents. Plan for j: https://claude.ai/artifact/Fhiz6ws6NsaDrivm97mAc1

## Goal

Evklid's own 3D atlas in the spirit of Astra's »Atlas človeškega telesa«, but more polished and in Evklid's look:
dark stage, Instrument Sans, accent `#6E9BFF`, rounded pill buttons. j's rule: every organ and organ system is also a
standalone simulation; plus 3D cells of every type, atom and orbitals, molecules, DNA, crystals, fields, solids,
3D graphs, solar system and cell processes. Web and the mobile app must look and work the same (the app opens the
same page in a WebView, like `/kalkulator`). Slovenian labels; no copying of Astra texts, images or models.

## Layout

Body layers (`sistem`): `koza`, `misice`, `okostje`, `sklepi` (joints, ligaments, cartilage), `organi`, `zile`,
`zivcevje` (incl. brain and sense organs), `limfni`. 3169 structures, about 1.6 M triangles, 16 MB.

## Hub and viewer page (`/3d`)

- **Hub** (`stran.js` `zbirka`): search over title, `opis` and area name (`iskanje.js`, no diacritics/case), area chips
  (Vse, Človeško telo = atlas + `organi` + `sistemi`, then each area), state in the hash (`#?p=celice&q=…`, replaced, so
  Back from a model returns to the same filter and scroll position). »Vse« shows the atlas card, »Nazadnje odprto«
  (localStorage `evklid.3d.nedavno`, last 8 ids) and one horizontal shelf per area with »Pokaži vse«; a chip or a search
  shows a grid. Search uses the Evklid keyboard (`tipkovnica-strani.js`; `html.k3-stran` defines the app tokens the
  keyboard reads).
- **Thumbnails**: `public/3d/slicice/<id>.webp` (560×350, transparent, ≤ 60 KB; `atlas.webp` is a cut-out of the body).
  Make them with `node scripts/3d-slicice.cjs [id …] [--manjkajoce]` after adding or changing a model; the server lists the
  existing ones in `seznam.json` (`slicice`), a model without one gets its area icon. `test/3d-zbirka.test.js` fails on a
  thumbnail without a model.
- **Model page**: `odpriModel(el, mod, { stran: true })` (lessons keep the old layout). Full-bleed stage plus a panel
  (`.k3-plosca`: Opis with `info.opis` and »Poskusi« from `info.poskusi`, the `nadzor` controls, »Deli« list): right of
  the stage at ≥ 900 px and on phones in landscape, below the stage on phones (the panel scrolls, the stage stays
  visible). Stage tools: zoom out/in (`kit.priblizaj`), play/pause, reset; a gesture hint until the first touch. Header:
  previous/next model of the same area (replaces the URL, so Back still goes to the hub), »1 od 29«, full screen (web
  only). Organ models (`postavitev: "organ"`) get the same panel; their `nadzor` stays on the stage and »Podrobnosti
  organa« is the last item of the panel.

## Model builder contract (code-built models)

```js
// public/3d/modeli/celice/zivalska.js
export const info = {
  id: "celica-zivalska",            // unique, ASCII, used in /3d#<id> and as sim engine id "3d-<id>"
  naslov: "Živalska celica",
  podrocje: "celice",               // celice | organi | sistemi | kemija | fizika | matematika | vesolje | procesi
  predmet: "BIO",                   // BIO | KEM | FIZ | MAT | NAR
  opis: "One or two Slovenian sentences for the hub card.",
  poskusi: "One Slovenian sentence: what to try (shown as »Poskusi: …« under the model in lessons).",
  merilo: { m: 20e-6, oznaka: "20 µm" },   // real size of the group's unit sphere diameter, for the scale bar
};
export function zgradi(THREE, ctx) {
  // ctx = { kakovost: "nizka" | "visoka", gibanje: true|false (false = prefers-reduced-motion),
  //         zacetek: { <nadzor id>: value } (start values from a catalog entry or /3d#<id>?telo=valj) }
  // Text labels: canvas sprites inside `group` (the kit has no label API).
  return {
    group,          // THREE.Group centred at the origin, fitting a sphere of radius 1
    deli: [         // tappable parts (list + part window next to the stage)
      { id: "jedro", ime: "Jedro", opis: "Hrani DNK in upravlja delovanje celice.", barva: "#7a68d8",
        meshes: [mesh1, mesh2], tocka: [x, y, z] },
    ],
    nadzor: [       // optional controls rendered by the kit (Evklid slider/segmented look)
      { tip: "drsnik", id: "t", oznaka: "Čas", min: 0, max: 1, korak: 0.01, vrednost: 0, ob: (v) => {} },
      { tip: "izbira", id: "pogled", oznaka: "Prikaz", moznosti: [["kroglice", "Kroglice in palčke"], ["kalota", "Kalota"]], vrednost: "kroglice", ob: (v) => {} },
      { tip: "gumb", id: "spusti", oznaka: "Spusti preizkusni naboj", ob: () => {} },
      { tip: "stikalo", id: "mreza", oznaka: "Pokaži mrežo", vrednost: false, ob: (v) => {} },
      { tip: "izpis", id: "v", oznaka: "Prostornina", vrednost: () => "V = 24,0 cm³" }, // read-only, re-read after each change and ~4×/s
    ],
    korak(t, dt) {}, // optional animation step (seconds); skip motion when ctx.gibanje is false; return false when idle (no redraw)
    korakBrezGumba: false, // optional: true hides the play/pause button (korak only eases a transition, e.g. telesa camera)
    izberi(delId, hit) {}, // optional: called on selection; hit = { object, instanceId, point } from the raycast (null from the parts list); may return another part id
    merilo: null,     // optional: object like info.merilo, or a function () => ({ m, oznaka }) | null (null hides the bar); re-read like `izpis`
    povzetek: null,   // optional: () => string, a short chip at the top left of the stage (e.g. V and P of a solid); stays visible while a slider is dragged; re-read like `merilo`
    pogled: [0.35, 0.3, 1], // optional: camera direction from the origin (model space) on open and »Ponastavi«; array or () => array, read each time
    luci: true,      // optional: false = kit removes scene.environment and its own lights while shown (model brings its own Sun)
    dispose() {},    // optional
  };
}
```

»Poglej pod povečavo«: any part (code `deli[]` or organ JSON `deli[]`) may have `povecava: "<model id>"` (and `la`, the
Latin name shown under the card title). On the /3d page the part card then shows a button that opens `/3d#<model id>`
with `history.pushState({ k3Iz: "povecava" })`, so Back (button, key, Esc) returns to the organ; in the app frame
(`?vgrajeno=1`) the same history works inside the iframe. Lessons get no button (`opts.povecava` is only passed by
`stran.js`). Chain: organ (oko → mrežnica) → tissue section (`organ-mreznica`, `organ-mesicki`, `organ-nefron`,
`organ-jetrni-reznjic`, code-built in `modeli/organi/`) → cell (`celica-*`). Test: `test/3d-povecava.test.js`.

Any nadzor item may have `vidno: () => boolean`; the kit hides it when false and re-checks after every `ob()`.
The kit frames the radius-1 sphere to the narrower of the horizontal and vertical field of view (portrait phones).

## Part window and framing (j, 2026-11-05)

- **Never over the model.** No coloured dots or label cards on the stage. The selected part's window (`.k3-info` in
  `pregledovalnik.js`: colour dot, name, `la`, `opis`, »Poglej pod povečavo«, ×) is the first item of the panel next to
  the stage: right of the stage on wide screens, a sheet under the stage on phones (the panel scrolls to it), under the
  stage in lessons. Closed by ×, Esc or a tap on empty stage (× and Esc return focus to the part's list button). A tap
  on the model scrolls the panel to the top; a pick from the list only scrolls as far as needed to show the window; in
  lessons the page scrolls the window into view when it is below the screen edge. The part name is also announced
  through a separate, always-present `role="status"` element. The body atlas does the same with `.a3-kartica`
  (`uskladiKartico`): when the card is open the stage shrinks (phone portrait: card and bottom row become a sheet under
  the stage; desktop and phone landscape / low 3D-world iframe: a content-high column left of the stage, stage
  background under it) and the fly-to centres the part in the stage below the header. The start frame
  (`ponastaviPogled`) uses the same free area, so the skull is never under the toolbar.
- **What is tappable** is shown by a soft glow instead of dots: when a set of parts is first shown (open, view switch,
  phase), one instance of each part glows twice in its colour (`namigniDele`, additive overlay mesh flagged
  `userData.k3Sij`, not pickable); parts wrapping almost the whole model (membrane, wall) do not glow.
- **Selection** tints every mesh of the part (all instances of an `InstancedMesh`, e.g. all mitochondria) with an
  emissive copy of its material in the part colour; parts smaller than 0.6 of the model (opaque, front-sided meshes)
  also get a thin accent outline like the atlas (`narisiObris`, back faces pushed out ~1.8 px, `userData.k3Sij`), so
  thin pale parts such as the axoneme show it. Copies and outlines are disposed on the next selection, rebuild and
  `unici()`. `deli[].tocka` is still required
  (contract, tests) but no longer drawn.
- **Framing** (`public/3d/kader.js`): `obsegVidnega` = box of what the camera really sees (visible branches, layers,
  visible materials; no lines, sprites or glow). On open and »Ponastavi« the camera frames that box's sphere (organs and
  models with `okvir` keep their own frame; never larger than the start sphere, never below 0.6 of it). After an `izbira`
  (e.g. spermij »Glava in vrat (povečano)«), a part selection or a deselection the camera moves only when the visible
  model changed noticeably (`drug`: centre moved > 0.2 r or radius × 1.25, e.g. a membrane or wall hidden or shown
  again) or the model or part is wholly out of frame (`vidnaKrogla`). While the camera is still in the last automatic
  frame it also keeps the model and part wholly in frame (the phone panel shrinks the stage); a frame the user zoomed or
  moved is otherwise kept. Builders need not frame views themselves.
- **Check**: `node scripts/preveri-3d-okna.cjs [id …]` (Playwright, swiftshader, phone 390×844 and desktop 1280×800;
  `atlas` also 844×390 landscape): for every cell and organ (and `atlas`) it opens the model, clicks every `izbira`
  option and the first and last part, and fails when ≤ 99 % of sampled vertices are in frame, a visible mesh is wholly
  out of frame, there are dots on the stage or the part window overlaps the canvas. `test/3d-kader.test.js`
  covers `kader.js` and that the viewer draws nothing over the stage. Run it after changing a cell/organ model or the
  viewer layout.

Kit behaviours builders may rely on: the viewer (`pregledovalnik.js`) turns models freely around the target like a ball in the hand (`opts.prostoVrtenje`, `public/3d/vrtenje.js`: camera and its up vector rotate together, no locked vertical axis, no pole stop; Ponastavi and view switches stand the camera upright again with `poleti(…, { pokonci: true })`); the body atlas keeps an upright orbit; a round button in the stage toolbar of every model and the atlas (`poveziGumbVrtenja`) cycles the mode »prosto« → »pokoncno« → »hoja« (`kit.nacinVrtenja`, stored as `evklid.3d.vrtenje` for all models): »hoja« is a first-person view (drag looks around, W A S D / arrows / Q E, wheel, pinch, and the held Naprej/Nazaj buttons at the stage edge move; OrbitControls is off and the target stays in front of the camera); `renderer.localClippingEnabled = true` (material.clippingPlanes work); the canvas is
transparent and the stage colour (`#0e131c`, plus a soft radial glow) is CSS behind it, so it is exact with or without
post-processing; at `visoka` GTAO only darkens opaque single-sided meshes: transparent, non-normal-blending and
double-sided materials, lines, points and sprites are drawn after the AO pass and never darkened;
`raycaster.params.Points.threshold = 0.02` (a tap hits a point cloud only near a point); on a
~4×/s tick the kit re-reads `vrednost` of drsnik/stikalo/izbira (builders may move their own slider or switch off
»Predvajaj«) and updates a widget only when `vrednost` changed since the kit last read it (never forces it back) and re-reads `deli` (may be a getter); picking takes the nearest intersection by distance (a mesh may override `raycast`).

After every `ob(...)` call the kit re-reads `deli` (the array may be replaced), `merilo` and rebuilds the parts list, so one builder can switch content (molecule, element, lattice, field type). `three` is a dependency pinned to
0.186.1 in package.json; tests may import it from node_modules.

Rules for builders:
- Import nothing; use the `THREE` passed in. No network access, no textures from other sites; generate textures in
  code (canvas) when needed.
- Look: `MeshPhysicalMaterial` with soft sheen/clearcoat for wet biological surfaces, matte for bone/minerals; colours
  readable on the dark stage (`#0B0F16`). Keep under about 150k triangles at `visoka` and 60k at `nizka`, and under 60
  draw calls (use `InstancedMesh` / merged geometry for repeated parts).
- Science first: real proportions where they matter, correct names (Slovenian school terms), state simplifications in
  `opis`. Orbitals and fields are computed from the equations, not drawn by eye.
- Every part has a Slovenian `ime` and a one-sentence `opis` a 13-year-old understands.

In lessons: a `public/sim/katalog.js` entry `["3d-<id>", "<title>", { zacetek: { <nadzor id>: value }, poskusi: "…" }]`
opens the model with those start values; `poskusi` (topic-specific) wins over `info.poskusi`. The viewer's reset button
carries `data-reset`. Check 3D entries with `SIM_FILTER='^3d-' node scripts/preveri-simulacije.cjs`.

## Organs from GLB (»Organi v 3D«: možgani, srce, oko, pljuča, ledvica, jetra …)

Real-anatomy organs come from Z-Anatomy meshes (brain cortex from MRI, eye globe from HuBMAP, see below), not from code. Files per organ `<o>`:
`public/3d/modeli/organi/<o>.js` (6 lines: `info`, `export const organ = "<o>"`, `zgradi = (THREE, ctx) => ctx.organ(organ)`;
listed in `organi/index.js`, so it is `/3d#organ-<o>` and sim engine `3d-organ-<o>`), `public/3d/modeli/organi-3d/<o>.glb`
(desktop, ≤ ~300k triangles, ≤ 6 MB), `<o>-telefon.glb` (≤ 90k, ≤ 2 MB, used at kakovost `nizka`) and `<o>.json`.
GLBs are dedup + KHR_mesh_quantization only, **no meshopt/draco/KTX2**: lessons run under the app CSP without WebAssembly.
Brain cortex comes from MRI, not Z-Anatomy: `skorja_mri` in the exporter replaces the Z-Anatomy gyri (tissue `skorja`)
with the FreeSurfer pial surfaces of OpenNeuro ds000001 fMRIPrep `sub-01` (CC0; `lh/rh.pial`, `.sulc`, `.aparc.annot`
downloaded to a folder passed as `--mri <dir>`), scaled into the Z-Anatomy cerebrum box so cerebellum, brainstem and
midline structures still fit; lobes come from the Desikan-Killiany parcellation (medial wall dropped), sulcal depth
darkens the baked AO and is kept in `COLOR_0` for the viewer (G = sulc, B = local depth = sulc minus its 40-step smoothed
version, 0.5 = sulcal lip): `brazde`/`vrh` tint sulci redder and crowns paler, `zile` draws fine pial vessels as
anti-aliased iso-lines of the local depth plus warped-noise branches (shader only, same on phone, no texture), `listi`
draws cerebellar folia; the FreeSurfer medial wall becomes tissue `sredina` (part `""`, unpickable, drawn behind the
midline structures in the cut via `vrstni`/`brezGlobine`), and both hemispheres are pushed ≥ 0.4 mm off the midline so
the cut never shreds them. Eye globe comes from HuBMAP HRA (`--hra <dir>` with `3d-vh-m-eye-l.glb`, CC BY 4.0): sclera,
cornea, iris (sculpted crypts), lens, zonules, ciliary body/processes, choroid, retina, optic disc, vitreous; aligned
onto the Z-Anatomy sclera (centre, size, corneal axis, optic-nerve exit) so Z-Anatomy muscles and optic nerve fit; the
HRA disc plug is flattened to the retina, macula and retinal vessels are drawn by the retina shader (`mreznicaZile`),
iris fibres/collarette/limbal ring by `sarenica`. Compared on 2026-11-04: the HRA heart (chambers and valves only, no great
vessels or coronaries, LV 9k triangles) is less complete than Z-Anatomy, so the heart stays Z-Anatomy. Available but unused (heart
trial 2026-11-04 looked worse): `odprtost` puts long-ray openness into G (exterior 1, cavities 0) so `mascaZunaj` keeps
epicardial fat off chamber walls, `rezVlakna` streaks cut caps, `tekstura.po_vozliscih` bakes each node from its own
high mesh (no vessel imprint on the myocardium). Optional baked textures (`tekstura`; tried on the Z-Anatomy brain, now unused, meant for heart/eye): shared UV atlas, normal map
and a base-colour *multiplier* (crevices darker/redder, blotches, fine vessels) baked in Cycles from a subdivided +
displaced copy, WebP 2048 px desktop / 1024 px phone, MikkTSpace tangents exported. `organ.js` uses them as
`map`, `normalMap` and `clearcoatNormalMap` on every tissue (`tkiva.<t>.tekstura: false` opts a tissue out,
`normala` scales the normal map); textures load through `TextureLoader` because the app CSP has no `blob:` in connect-src.

Lungs, kidney, liver (2026-11-04, sources compared per organ): **pljuča** = Z-Anatomy (5 lobes, trachea, bronchi to
segmental level, pulmonary arteries/veins; HRA `lung-male` has nicer cartilage-ringed bronchi but no trachea or vessels and
coarse segment meshes). **ledvica** = HRA `kidney-male-left` (capsule, cortex, renal columns, 9 pyramids + papillae, sinus;
CC BY 4.0, `viri.json` `hubmap-hra-ledvica`) aligned by `poravnava: "pca"` (centroid, principal axes, scale) onto the
Z-Anatomy kidney so its ureter, renal artery/vein and adrenal fit; HRA has no renal pelvis or intrarenal vessels and the
Z-Anatomy ones stay excluded (`IZLOCI`): `dodaj: ["ledvicni_meh"]` builds our own pelvis with major/minor calyces from metaballs (cups on each HRA papilla → two major calyces → pelvis → plugs the Z-Anatomy ureter, cut 12 mm below the pelvis; the HRA sinus sheet is dropped, adrenal ×0.72 from its base). **jetra** = Z-Anatomy (segments I–VIII grouped
into right/left/quadrate/caudate lobes, gallbladder, bile duct, portal vein, hepatic artery and veins; HRA `liver-male`
has a denser capsule but no gallbladder, portal vein or hepatic veins); `dodaj: ["jetrne_zile"]` grows our own branching portal and hepatic vein trees (tubes, bifurcating, kept ≥ radius + 1 mm under the outer liver surface, segment borders ignored) so the cut shows vessel rings. Lungs: segmental bronchi/vessels have their own tissues (`dihalna-v`, `pljucna-*-v`) hidden in `celota` (their ends poke through the lobes) and shown in `prerez`. Exporter options added for them: `debelina`
(SOLIDIFY inwards: hollow bronchi/vessels, a ring with a lumen in the cut), `skrci` (move vertices inwards along the
normal: subdivided neighbouring lobes overlap by ~1 mm at concave fissures, so the neighbour's front face would cover
the cut cap), `napihni` (scale about the centroid; HRA: `zapri` fills the papilla opening of each pyramid, pyramids
×0.965 and columns ×0.988 so their back-face caps sit in front of the socket walls). Cap pattern `rezPore`/`rezPoreMoc`
(spongy lung, liver lobules). Desktop limit for these untextured organs is 4 MiB (test).

Studio look for organs (2026-11-08, viewer only, no re-bake): `studioNaprave()` (`scena.js`) is true except on weak
devices (`deviceMemory` ≤ 2, Save-Data, app `lite` mode; override `?studio=0|1` or storage `evklid.3d.studio`), and
then `zgradiOrgan` asks the kit for `nastaviOkolje("studio")`: IBL from Poly Haven »Studio Small 09« (CC0,
`modeli/okolje/studio_small_09_512.hdr`, 512 × 256, 0,5 MB, credited in `viri.json` `polyhaven-studio`; loaded once per
scene in parallel with the GLB, RoomEnvironment until then or on error). Materials: opaque tissues with `lak` ≥ 0,45
(not `suho: true`) get clearcoat clamped to 0,6–0,8 and `lakHrap` to 0,15–0,3; cheap translucency without
transmission: fat in grooves (`masca`, strength `mascaPresevnost`, default 0,45) and opaque double-sided sheets such as
valve leaflets (`presevnost`, default 0,35; 0 = off) add back-side environment irradiance (one extra env sample).
Cut caps stay `MeshBasic`; a selected part (teaching colour) drops clearcoat to 0,1. Weak devices keep the old look exactly.

Viewer extensions (pregledovalnik.js, generic, all builders may use them):
- `zgradi()` may return a Promise; the viewer shows a loading card (`ctx.napredek(0–1)`) and an error card on failure.
- `ctx.naloziGLB(pot, napredek)` → Promise of the raw glTF scene (path relative to `public/3d/modeli/`, cached);
  `ctx.organ(ime)` → Promise of a full organ model (`public/3d/organ.js`); `ctx.t` = i18n.
- Model fields: `postavitev: "organ"` (full-height warm stage, controls float on the stage, parts as one scrolling row),
  `podrobnosti: { naslov, odseki: [{ naslov, besedilo }] }` (»Podrobnosti organa« pill → sheet; Esc closes),
  `okvir: () => ({ sredisce, polmer })` (camera target and radius on open/reset), `ao: () => bool` (GTAO off while
  clipping: the GTAO normal pass ignores clipping planes), `deli[].skrijTocko` (legacy, ignored: nothing is drawn on the stage),
  `nadzor[].ponastaviPogled` (after `ob()` deselect and fly to the new `pogled`/`okvir`).

`<o>.json` (hand-written, Slovenian, Opus only): `tkiva` (per tissue key from the exporter: `barva`, `hrap`, `lak`,
`lakHrap`, `sijaj`, `sijajBarva`, `rob`/`robBarva` (rim »subsurface«), `ao`, `zrno`, `f`, `relief`, `lise`, `senca`/
`sencaBarva` (warm crevice tint), `masca`/`mascaBarva` (fat in grooves), `prosojnost`, `fresnel`, `dvostransko`,
`rez` (cut-cap colour), `brezReza`), `deli` (`id` = exporter part, `ime`, `la`, `opis` one sentence for a 13-year-old,
`barva`, optional `tocke: { celota: [x,y,z], prerez: [x,y,z] }` in metres in GLB coordinates (GLB origin = bbox centre at export), else
an automatic outer point), `prerez` (`ravnine: [{ n, d }]` keep `n·p + d ≥ 0`, metres in GLB coordinates, `presek: true` = remove only the
intersection, e.g. a quadrant), `pogledi.celota|prerez` (`pogled` camera dir, `okvir`, `tocke` (legacy point ids, not drawn), `skrijStran: "r"`,
`skrijTkiva`, `skrijDele`, `rez: false`, `tkiva: {<tkivo>: {barva, prosojnost, dvostransko, sijaj, lak}}` per-view overrides, e.g. a dark pupil), `luci` (extra directional lights), `podrobnosti` (5 paragraphs: Zgradba,
Delovanje, Zanimivost, bolezni/poškodbe, Kako skrbimo zanj). `deli[].vozlisca`, `velikost`, `trikotniki` are written by
the pipeline (`velikost` = bbox diagonal at export, the AO ray scale; it stays the export value after a vessel repair).
All JSON lengths (cut planes, `tocke`, `okvir.sredisce`, shader centres) go through `public/3d/organ-prostor.js`:
the model is recentred on its bbox at load, and a mesh post-process can move that bbox (the rebuilt aortic arch moved
the heart's centre by 5.5 mm), so never multiply a JSON length by the scale alone (`test/3d-organ-prostor.test.js`). Cut caps: each opaque mesh gets a child drawn with back faces in the `rez` colour, visible only in
`prerez`, so cut walls look solid. Picking uses a vertex-clustered proxy (~10× fewer triangles)
and ignore hidden and clipped-away parts. Test: `test/3d-organi-glb.test.js`.

Pipeline for a new organ (e.g. `jetra`):
1. Add an entry to `ORGANI` in `scripts/atlas/izvozi-organe.py`: `vkljuci`/`izkljuci` regex on »name / parent /
   grandparent …« (find names with `atlas-strukture.json` rows or a Blender listing), `tkiva` and `deli` (regex → key,
   first match wins; `blizina` assigns leftovers to the nearest part), `cilj` (desktop, phone triangles), optional
   `gladi` (extra SUBSURF for low-poly meshes), `skatla` + `jedro` (clip vessels to a box around the organ),
   `krivulja` (curve resolution), `znotraj` (delete parts of a mesh inside another). The NC exclusion `IZLOCI` must
   stay (inner ear, kidney pelvis/intrarenal vessels: build those in code if needed).
2. `blender -b --factory-startup --python scripts/atlas/izvozi-organe.py -- <raw> --blend <Startup.blend> [--mri <dir>] [--hra <dir>] <o>`
   (links objects instead of opening the file: opening needs > 11 GB). It centres, fixes normals, decimates, bakes
   ray-traced AO into `COLOR_0` and writes `<raw>/<o>.glb`, `<o>-telefon.glb`, `<o>.vozlisca.json`.
3. Write `public/3d/modeli/organi-3d/<o>.json` (texts, tissues, views), then `node scripts/atlas/organi.mjs <raw> <o>`
   (quantize into `organi-3d/`, fill `vozlisca`). Add `organi/<o>.js` and the index entry.
4. Tune with screenshots at 390×844 and 1440×900 (Playwright + swiftshader), set `tocke`, `okvir`, cut planes;
   `npm test`. `organi-3d/*.glb` is already covered in `public/3d/viri.json`.

## Mesh check (all GLBs)

`node scripts/atlas/preveri-mreze.mjs [filter …] [--vse] [--json]` checks every GLB in `organi-3d/`, `telo/` and
`telo-hd/` (~4 s for all 29): per node (part) open edges and holes (boundary loops, with perimeter in mm; an open tube end
is a loop too), non-manifold edges, flipped faces (minority winding per connected component), closed components that are
inside-out (signed volume < 0, mirrored nodes accounted for; a negative closed component inside a positive one is a
cavity, i.e. the lumen of a vessel with a real wall, and is fine), degenerate triangles and non-triangle primitives
(strips, fans, lines: counted as a problem, never skipped); vertices are welded by position first, across all
primitives of a node. Vessel parts are marked (organs: `extras.tkivo` arterija/vena/portalna/pljucna*; body: `sistem` `zile` of
`extras.zid` without heart chambers and valves). `test/3d-mreze.test.js` fails when any part gets worse than
`scripts/atlas/mreze-izhodisce.json`; after a mesh fix lower the baseline with `--izhodisce` (it refuses increases
unless `--sprejmi-slabse`). Reading needs the devDependencies `@gltf-transform/core`, `@gltf-transform/extensions` and
`meshoptimizer` (decoder for `telo/`).

## Vessel repair (after every export)

`node scripts/atlas/popravi-zile.mjs [filter …] [--suho]` post-processes the exported GLBs in place (geometry in
`scripts/atlas/zile-mreza.mjs`, plan per model in `NACRT` at the top of the tool, driven by part names; UVs, materials,
part names and quantization/meshopt are kept). Run it again after `izvozi-organe.py` or a body export; a second run
changes nothing. One file: `--vhod a.glb --izhod b.glb --nacrt srce|jetra|telo`. Steps:

- `dopolni`: a vessel wall cut off along its length by the export box (`skatla`: lens-shaped hole, trough of the aortic
  arch) is rebuilt on the cylinder of the tracked tube axis; a loop that winds around the axis is a tube end and stays.
- `zgosti`: faceted great vessels (12 sides in the heart, 6 in the body) are refined adaptively: an edge is split where
  the smooth surface through its end points and normals (PN-triangle curve) deviates from the chord by more than the
  tolerance in `NACRT.<plan>.zgosti(path)` (heart 0.15 mm desktop, 0.44 mm phone = aorta only; body 0.3 mm HD, 0.7 mm
  regular), the new vertex lies on the curve, straight edges stay; two passes (6 → 12 → 24 sides), conforming mesh.
- `stiki`: end rings of neighbouring parts of one vessel get identical vertices and normals; rings with different
  vertex counts get the union of their vertices (boundary edges split), three-way junctions are iterated until equal.
- seam smoothing: Taubin smoothing (no shrinkage) around part junctions and the rebuilt wall, both parts together,
  fading with distance; free ends and rings shared by three parts (a bifurcation whose branches start in the same
  ring and overlap) stay; normals of the smoothed parts are recomputed from geometry.
- `stena`: great vessels get an inner wall and flat rims at open ends (aorta 2.5 mm, pulmonary trunk and arteries
  1.5 mm, venae cavae and pulmonary veins 1 mm; thinner where the tube is narrow or the wall folds). Ends that are not
  visible (a junction with another part, or an end inside a neighbouring vessel) get a rim built from the wall
  vertices, so no flat-shaded ring shows through a junction or pokes out of the neighbour. An end that continues
  into a small solid vessel (brachiocephalic vein → subclavian and jugular vein) is treated as hidden all round.
- `polna`: small vessels (coronaries, cardiac veins, all other body vessels) become closed solid tubes (end caps).
- `zakrpaj` (liver): small holes are filled first; `usmeri`: winding made consistent, outside out. A component nested
  inside closed shells of the same part (the lumen of a hollow vessel; sampled points, union of shells) is never
  flipped; the mesh check uses the same rule.
- Organs: the vertex-colour data of changed parts (R baked shade, G openness for the heart) is baked again in JS with
  the same rays as the exporter (ray length from `velikost` in the organ JSON); coincident vertices of two parts get
  the average shade.

Because the walls are real, heart parts no longer use `znotraj` in `deli` (double-sided wall, #531); the support in
`organ.js` stays for single-wall tubes. Known limits: branches are overlapping tubes, not boolean unions; the aortic arch
has no branch stubs; `Cavernous sinus` (body) keeps tiny holes in a non-manifold mesh; the phone heart refines only the
aorta (90,000 triangle limit). `--vhod a --izhod b` with nothing to repair copies the input. `test/3d-popravi-zile.test.js`
checks the steps on synthetic tubes. Update `trikotniki` in the organ JSON after a repair.
