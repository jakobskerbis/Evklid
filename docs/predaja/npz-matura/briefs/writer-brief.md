# Brief: Opus writer of one Evklid practice paper

You write one original practice exam paper for Evklid, a Slovenian AI STEM tutor app (repo /home/user/Evklid, Node 22), in Slovenian, for students preparing for the Slovenian national exam named in the paper id (NPZ 6 / NPZ 9 = primary school 6th / 9th grade; MATURA = gimnazija matura, OR osnovna raven, VR višja raven; POKLICNA = poklicna matura).

## Copyright (owner's rule, strict)
Use ONLY the structure file `content/exam-papers/structures/<id>.json` (or the entry in `server/our-paper-structures.js`). Never look up, download or read the original RIC paper, never search the web for it. Tasks must be entirely original: own numbers, contexts, names, organisms/compounds-in-context, figures and wording.

## Format
Read the header comment of `server/our-papers.js`. Output `content/exam-papers/<id>.json`:
`{ id, exam, subject, minutes, points, author: "AI", tools, polas?, sections?, tasks: [...] }` with exactly the structure's tasks in the same order: same `pola`, `section`, `n`, number of parts and points per part (`structure.tasks[i].points`), and the part formats from the structure. Copy `polas` (pola, minutes, and a one-sentence `tools` per pola in Slovenian) and `sections` (short Slovenian titles) from the structure when present. Part ids are "a", "b", … (a task with one part may use id ""). When the structure has `maxListed` (candidate chooses tasks), set top-level `maxPoints` to the structure's `points` and `points` to the sum of all listed parts. Write all student-facing text in ti-form (also matura), explanations included. Scratchpad is shared with other agents: put your generator and figures in your own folder named after the paper id (e.g. scratchpad/w-<id>/), never in a shared folder.
Easiest: write a generator script `/tmp/claude-0/-home-user-Evklid/c92b5c82-a2fd-5a5c-a1b4-eeb69e57bb18/scratchpad/paper-<id>.mjs` that builds the object with String.raw for LaTeX and writes JSON.stringify(obj, null, 1); run it with node. Long papers: build the tasks in a few chunks (several smaller files imported by the generator) so each Write stays manageable.

## Quality (student-facing content: quality first, never shorten)
- Each part: `text` (what the student sees; shared context in task.intro), `format`, `answer` (short final answer), `ways` = explanations: ≥ 1 per part, ≥ 2 genuinely different ways for parts with ≥ 2 points (e.g. »Po korakih«, »Drugače: …«, »S sliko«, »Preizkus«, »Z oceno«). Each way is a clear worked solution with intermediate results and the why. For word/calculation problems the first way starts with **Podatki:** (all given data with units) and **Iščemo:**. `scoring` for parts ≥ 2 points in the style of the exam (how points are earned; must add up). `mistake` (a typical mistake and why it is wrong) where useful.
- Multiple-choice (`choice`): `choices` (Markdown/LaTeX) and `correct` (indices); the way explains why the right option is right AND why each wrong option is wrong (short). Distractors must be plausible, typical misconceptions.
- Level and terminology exactly of the target school level and the Slovenian curriculum; correct Slovenian; decimal comma in LaTeX (`$3{,}5$`), `\cdot` for multiplication, units `$5\,\mathrm{cm}$`, chemistry formulas with `\mathrm{}` (e.g. `$\mathrm{H_2SO_4}$`); respect the calculator rule of each pola (no calculator → numbers computable by hand).
- Figures (graphs, sketches, apparatus, tables as images if needed): inline SVG in task or part `figure`, viewBox-based, no fixed width/height, stroke/fill `currentColor` or neutral colours readable on light AND dark backgrounds (shading via fill-opacity with currentColor), labels as <text>, only drawing tags (svg, g, path, line, rect, circle, ellipse, polygon, polyline, text, tspan, defs, marker, use, title), no scripts/links/style/foreignObject, < 4 KB each. A figure next to the question must never reveal an answer; put finished constructions / solution sketches in `solutionFigure`. Data tables: Markdown tables in text/intro.
- Every number right: verify all arithmetic in one or two `node -e` batches, not mentally. Then run `node scripts/check-paper.js content/exam-papers/<id>.json` (shape, points vs structure, LaTeX, recomputed number steps, SVG) and fix until ✓.
- Don't read big repo files (never server/university-extra.js), don't modify other repo files, don't commit.

Final reply ≤ 5 lines: ✓/✗ from check-paper, number of tasks/parts, doubts.
